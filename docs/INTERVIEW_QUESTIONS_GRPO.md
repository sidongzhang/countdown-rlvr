## 阶段性实验答案（截至2026-09-08的20步Pilot）

以下只记录已经由真实日志支持的答案，不替代标准GRPO与Adaptive GRPO的正式对照结论。

### 数据与配置

- 数据处理（二-2）：固定随机种子42后，实际生成20,000条训练样本和512条验证样本；训练DataLoader有312个batch，验证DataLoader有8个batch。
- 双卡参数（七-2）：Prompt batch为64、group size为8，因此每次初始rollout生成64×8=512条Response。自适应重采样只会为零方差Prompt额外生成候选，不改变最终每组8条Response的结构。
- 指标设计（八-3）：本次日志同时确认训练group size=8与验证`val/pass@5`正常工作；两者分别服务于组相对优势和独立验证，数值不需要相同。
- 实验公平性（九-6）：训练DataLoader使用`TRAIN_SEED=42`固定shuffle顺序；每次验证通过`VAL_SEED=42`重置vLLM采样随机流。训练rollout不会为每次请求重复注入同一个seed，否则Adaptive重采样同一Prompt时可能复现原回答，失去重采样意义。

### 零方差重采样

- 零方差检测（五-4）：修复计数后的两次更新各处理64个Prompt组，分别检测到3个和2个零方差组；合计为5/128=3.91%。
- 恢复率（五-11）：两步分别恢复2/3和2/2个零方差组，聚合恢复率为4/5=80%；重采样后的零方差组由5/128降为1/128，即从3.91%降至0.78%。该数字只是两步样本，不能直接外推到正式长跑。
- 有效优势（五-12）：两步`effective_advantage_token_ratio`分别为86.0%和94.0%，算术平均为90.0%。
- 额外开销（五-13）：两步初始rollout平均耗时28.685秒，重采样平均耗时15.927秒；按两者比值计算，重采样增加约55.5%的生成阶段时间。单步波动较大，正式结论应报告100步正式实验均值。

### 稳定性与资源

- 显存（八-19、十一-7）：轮询观察到两卡最高显存约33.3GB/卡，低于单卡48GB容量；此值不是5秒间隔完整监控得到的正式峰值。
- 训练耗时（七-11、十一-6）：两次更新分别耗时60.752秒和73.692秒，平均67.222秒；初始生成平均28.685秒、重采样15.927秒、Reference前向4.444秒、Actor更新18.129秒，生成相关阶段是当前主要耗时来源。
- 训练稳定性（十-9、十-18）：两步`actor/grad_norm`分别为0.407和0.385，`actor/kl_loss`分别约为0和0.001，未出现NaN或CUDA OOM；冒烟成功只证明链路可运行，不能证明更长训练过程中不会发生累积不稳定。
- 输出诊断（八-10至八-14）：两步Format rate平均81.65%，合法表达式率平均17.9%，正确率平均1.9%，Response截断率平均5.85%。这说明初始阶段模型多数能遵循标签格式，但生成可验证且正确的算式仍是主要瓶颈。

### 阶段性验证结果

- 原始模型结果（十一-1）：在固定512题、每题5次采样、验证种子42下，未训练Qwen2.5-1.5B-Instruct的pass@1为5.08%（26/512），pass@5为16.80%（86/512），Format rate为75.86%（1942/2560），合法表达式率为21.48%（550/2560），平均分层奖励为0.1327。这是后续标准GRPO和Adaptive GRPO的正式共同基线。
- 在完成2次参数更新后进行的512题、每题5次采样验证中，pass@1为4.10%、pass@5为15.82%、Format rate为80.04%、合法表达式率为21.41%。由于评估发生在2次更新之后，这组数字不能填写为“原始模型基线”，也不能代表Adaptive GRPO最终效果。
- 标准GRPO 20步Pilot：最终pass@1为13.28%（68/512）、pass@5为30.47%（156/512）、Format rate为100%、合法表达式率为98.48%（2521/2560）。相对原始模型分别提升8.20和13.67个百分点。20步平均零方差组比例18.52%，但后5步已升至47.50%；平均有效优势Token比例78.40%，后5步降至50.96%。这证明标准GRPO能快速学习格式与数字约束，同时也会迅速进入大量组无相对优势的阶段。
- 标准GRPO 20步性能：平均29.062秒/步，纯训练共581.236秒；5秒监控捕获GPU0/GPU1峰值48,124/48,208MiB。虽然未OOM，但不足1GiB余量不适合长跑，因此正式对照统一将vLLM显存比例从0.45降到0.40。
- Adaptive GRPO 20步Pilot：最终pass@1为14.26%（73/512）、pass@5为31.84%（163/512）、Format rate为100%、合法表达式率为98.95%（2533/2560）。相较同为20步的标准GRPO，pass@1提高0.98个百分点（多5题），pass@5提高1.37个百分点（多7题）。这是Pilot中的正向信号，但幅度较小，不能冒充100步或500步正式结论。
- Adaptive重采样效果：20步初始零方差组共225/1280=17.58%，最终为128/1280=10.00%；共恢复97/225个组，聚合恢复率43.11%。平均有效优势Token比例86.43%，较标准组高8.03个百分点；后5步为63.48%，较标准组高12.52个百分点。第20步初始零方差达到42/64，一次重采样只恢复5组，说明模型输出趋同时恢复难度会增加。
- Adaptive性能开销：平均38.086秒/步，20步纯训练761.723秒，比标准组慢31.05%。初始Rollout、重采样、Reference前向和Actor更新平均耗时分别为15.508、7.887、3.146和11.501秒。GPU0/GPU1峰值为48,388/38,552MiB，因此正式对照统一使用`GPU_MEMORY_UTILIZATION=0.40`。
- Adaptive稳定性：第4步记录到一次裁剪前`grad_norm=13.088`，梯度裁剪阈值为1.0；下一步恢复到0.387，其余19步均值0.339，未发生NaN、OOM或连续发散。最终KL为0.099、策略熵为0.400，后续需同时监控KL、熵和有效优势，而不能只看Reward。
- 正式长度决策（九-7、九-10）：首阶段两组各完整运行100步，每20步验证，主结果预先约定为第100步，避免根据同一验证集挑最好Checkpoint造成乐观偏差。标准组每20步保存，Adaptive因磁盘空间只保存第100步。选择100步是因为20步时格式已饱和、后期零方差快速增加且Adaptive熵降至0.400；只有80到100步仍持续提升且稳定性指标正常时，才重新安排300或500步长跑。

### 100步正式实验答案

- 最终效果（五-22、十一-1至十一-4）：标准GRPO的pass@1/pass@5为29.69%（152/512）和31.84%（163/512），Adaptive GRPO为29.30%（150/512）和32.23%（165/512）。Adaptive的pass@1低0.39个百分点、pass@5高0.39个百分点，均只差2道题，不能声称稳定提高最终准确率。两组相对原始模型都获得了显著提升。
- 学习曲线（九-8、九-10、九-12）：Adaptive在第20步pass@5为32.23%，比标准组27.34%高4.88个百分点；第40步为34.57%，比标准组31.25%高3.32个百分点。但第60和80步转为落后，第100步基本持平。这说明重采样带来早期样本效率优势，却没有保持到最终Checkpoint；主结果按预先约定报告第100步，不能事后只挑第40步。
- 有效信号（五-11、五-12、十一-3）：100步中Adaptive共重采样4016个Prompt组、恢复363个，聚合恢复率9.04%；平均零方差比例从62.75%降至57.08%，平均有效优势Token为41.85%，比标准组34.65%高7.20个百分点。它证明机制确实增加了有效训练信号，但有效信号数量不是泛化质量的充分条件。
- 恢复率衰减（五-19、十-1、十一-10）：Adaptive恢复率在五个20步阶段依次为62.42%、14.88%、8.83%、4.78%和2.47%。后期模型输出高度趋同，对所有零方差Prompt无差别补采样的边际收益很低；下一版应增加在线恢复率门控或Prompt难度筛选，而不是直接把重采样次数从1增加到2。
- 性能代价（五-13、七-11、十一-6）：扣除周期验证和Checkpoint保存后，标准与Adaptive平均每步分别为21.006和28.153秒，总纯训练时间分别为2100.612和2815.295秒，Adaptive开销为34.02%。Adaptive平均初始Rollout为9.474秒，额外重采样为6.927秒。
- 显存与磁盘（六-15、八-19、十一-7）：标准组GPU0/GPU1峰值48,508/48,456MiB，Adaptive为48,452/47,872MiB，`gpu_memory_utilization=0.40`下均无OOM。标准组5个Checkpoint占34GB，数据盘剩余空间不足以再保存Adaptive的5份，因此Adaptive保持每20步验证但只保存第100步；保存频率不参与训练计算。
- 稳定性（十-9、十-12、十-18）：两组均无NaN或OOM。标准组最大梯度范数0.571；Adaptive第10步出现一次裁剪前`grad_norm=10.437`，阈值1.0完成裁剪，第11步恢复0.447，未形成连续发散。最终KL分别为0.172和0.195，策略熵分别为0.184和0.176。
- 是否继续500步（九-7、九-10）：不继续。80到100步Adaptive没有形成稳定精度优势，后20步恢复率仅2.47%，继续无差别重采样主要增加成本。应先改进重采样预算策略，再做新的对照实验。

### PPO 60步对照答案

- 对照目的（十三-1）：补充PPO不是为了预设GRPO一定更好，而是把“不需要Critic”从概念优势变成同硬件、同数据与同rollout预算下可量化的效果和成本对比。三组前60步都处理64个Prompt/步、8条Response/Prompt，共30,720条训练Response，并复用同一512题验证集。
- 验证曲线（十三-11、十三-12）：PPO在Step 0/20/40/60的pass@1分别为5.08%、7.62%、16.21%、23.63%，pass@5分别为16.80%、23.44%、34.38%、37.30%。第60步标准GRPO为26.37%/32.03%，Adaptive为24.02%/30.86%。所以PPO的单次命中率低于标准GRPO2.73个百分点，但五次采样覆盖率高5.27个百分点，不能用单个指标宣布某算法全面获胜。
- 统计边界（八-23、十三-15）：标准GRPO与PPO第60步pass@1的95% Wilson区间分别为22.74%–30.35%和20.16%–27.50%，pass@5分别为28.14%–36.19%和33.22%–41.57%，均有重叠。三组复用相同题目时更适合逐题配对检验，但当前未保存完整逐题布尔结果且只有一个训练种子，所以不声称统计显著。
- 多样性解释（十三-13）：第60步PPO的Token平均策略熵为1.841，标准与Adaptive GRPO分别为0.151和0.194。更高的熵与“pass@1较低、pass@5较高”共同表明PPO保留了更多答案多样性；这是日志支持的相关解释，不是严格因果证明。
- Critic诊断（十三-5至十三-8）：独立Critic复用Qwen骨干，但Value Head随机初始化。第1步`vf_explained_var=-214.036`，Step 21–40和41–60均值仍为-0.245和-0.132，第60步为-0.047。Explained Variance为0表示不比常数均值预测更好，小于0表示更差；即使后20步Value Loss均值只有0.0496，也不能说Critic已经学好，因为损失的绝对大小会受Return尺度影响。
- 训练成本（十三-9、十三-10、十三-14）：扣除验证时间后，前60步标准GRPO、Adaptive GRPO和PPO平均分别为23.752、29.759和53.113秒/步。PPO约为标准GRPO的2.24倍，其中Critic更新和Value前向平均占21.581和3.110秒/步。通过Critic参数与优化器CPU Offload、vLLM显存比例0.30，5秒监控捕获的两卡峰值为48,350/47,650MiB，全程无OOM或NaN。
- 截停口径（十三-16至十三-18）：实验因运行成本在第60步验证后截停。轮询中断存在延迟，日志又完整记录了第61、62次更新，并在第63步开始前退出；这两步没有新验证，不纳入60步结果。由于PPO关闭了Checkpoint保存，只能复核第60步日志，无法重新加载精确的第60步权重做新评测，这是本次实验的明确限制。
- 后续优化（十三-19、十三-20）：如果继续PPO，应优先改善Critic学习，例如检查Value目标尺度、Critic学习率/预热、增加Critic更新轮次或使用更合理的初始化，再观察pass@1是否提高。当前结论是GRPO具有更高的60步单次命中率和更低训练成本，PPO具有更高的pass@5覆盖率；这比“GRPO一定比PPO效果好”更准确。

### 环境排障

- 首次启动暴露了`uvloop 0.22.1`与Ray 2.42.1 worker导入不兼容，报错为`There is no current event loop in thread 'MainThread'`。本实验不运行vLLM HTTP服务，移除`uvloop`后Ray改用标准asyncio事件循环并成功启动。
- Hydra struct模式要求配置字段预先声明；`trainer.val_before_train`和`trainer.val_only`已经加入主配置，避免依赖`+field=value`临时追加字段。
- 旧循环的`TOTAL_STEPS`存在一次更新的off-by-one；冒烟日志发现后已修正，使配置值严格等于Actor参数更新次数。
- 首次20步标准GRPO Pilot在第15步出现32.8%零方差组，但有效优势Token比例错误显示100%。根因是float32的0.1奖励减均值后残留约1e-8，除以epsilon后形成伪非零优势。当前实现在组标准差不超过1e-6时显式将该组优势置零；该问题说明epsilon只能避免除零，不能替代零方差分支处理。
